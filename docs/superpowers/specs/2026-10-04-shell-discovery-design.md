# КОНСОЛЬ: программы, позиции и ключи — с машины, а не из таблиц

Дата: 2026-10-04

## Цель

КОНСОЛЬ подбирает имя программы из того, что установлено, для каждого
аргумента знает, что там ждут (путь, каталог, подкоманду, хост, службу), и
понимает ключи утилит. Перечней утилит, подкоманд и ключей в исходниках нет:
всё узнаётся на машине пользователя тем же способом, каким это делает Tab.

## Что сказал пользователь

- Консоль подбирает допустимые исполняемые файлы.
- Понимает позиционные параметры: где утилите нужен путь.
- Понимает параметры (ключи) утилит.
- Утилиты и прочее в исходниках не перечислять — обнаруживать автоматически.
- Таблица `WORDS`: оставить только исключения, до которых подбор не
  дотягивается; у каждого — замер, почему.
- Ключи: из man; если man-страницы нет — запуск `--help`.

## Допущения

- Источник знаний о позициях — установленный bash-completion (2.16 на
  Ubuntu 26.04, 1390 скриптов). Пользовательская оболочка — bash; что скажет
  Tab в его терминале, то знает и консоль.
- Буквы (`LETTERS`), символы (`SYMBOLS`), числа и синонимы каталогов XDG —
  это произношение, а не перечень утилит; они остаются.
- Короткие ключи из букв («минус эл эй» -> `-la`) работают как сейчас и не
  проверяются по списку ключей.
- `--help` запускается только у программ из PATH вне домашнего каталога,
  которые пользователь не может переписать: свой скрипт без разбора
  аргументов (`./create.riverport.sh`, он же в `~/bin` или `~/.local/bin` —
  они первые в PATH службы) выполнил бы на `--help` действие.

## Замеры (на этой машине, 04.10)

- Запрос к bash-completion отдельным `bash`: 20–50 мс (`git`, `systemctl
  --user`, `docker compose`, `apt`). Загрузка `bash_completion` — 16 мс.
- `compgen -c` — 90 мс, 3586 имён. `man ls` — 30 мс.
- Whisper на фразу тратит ~1 с; пять позиций по 50 мс — до 0,25 с сверху.
- PATH у службы `systemd --user` и у оболочки в терминале совпадает.
- Нечёткий подбор имени по всем 3586 программам (сходство лучшего, отрыв от
  ближайшего соперника, который не вариант того же имени — `dockerd`,
  `pytest-3`, `ping6` вариантами считаются):

  | сказано | лучший | сходство | отрыв |
  |---|---|---|---|
  | докер | docker | 0.91 | 0.24 |
  | кубектл | kubectl | 0.86 | 0.24 |
  | пайтест | pytest | 0.92 | 0.20 |
  | системктл | systemctl | 0.78 | 0.15 |
  | хед | head | 0.86 | 0.06 |
  | тач | tac (нужен touch) | 0.86 | 0.11 |
  | питон, клод, ходе, скрин | pon, kmod, node, strings | 0.67–0.75 | 0–0.08 |
  | слова намерения: покажи, сделай, плавать, сколько, останови… | — | ≤ 0.73 | — |
  | проверь (слово намерения) | prove | 0.91 | — |

  Порог слова намерения не отсекает («проверь» -> `prove` 0.91, замер
  05.10). Их берегут другие правила: нечётко подбирается только кириллица
  от 4 букв, а подобранное имя возвращается как сказано, если в команде
  остались русские слова — у нечёткого хоть одно, у точного транслита
  (`нет` -> `net`) два и больше, и все аргументы русские.
- Разбор справки: парсер самого bash-completion (`_comp_compgen help -`) на
  тексте `ls --help` дал 63 ключа.

## Устройство

```
whisper → _words → _lex → _glue → _fit(toks, cwd) → кавычки → строка
                                       │
                    complete.py ───────┤ programs()           имена программ
                    (без звука,        │ position(words, cwd)  что ждут на следующей позиции
                     без демона)       │ options(words)        ключи программы
```

### `complete.py` — новый модуль

Знает только bash, bash-completion, man и PATH. О демоне, звуке и правилах
`shell.py` не знает; проверяется без микрофона.

- **`programs()`** -> множество имён: `compgen -c` (исполняемые в PATH,
  встроенные, ключевые слова). Кеш сбрасывается, когда меняется mtime
  какого-либо каталога PATH.
- **`position(words, cwd)`** -> `(вид, кандидаты)` для позиции сразу после
  `words`, или `None`, если узнать не удалось. Один `bash` в каталоге `cwd`:
  `source bash_completion`, `COMP_WORDS = words + [""]`, `COMP_CWORD` —
  последний, `_comp_complete_load` программы — только если у неё ещё нет
  `complete -p` (`time`, `nohup`, `xargs` описаны в самом
  `bash_completion`), вызов функции из `complete -p`. Функции
  `_comp_compgen_filedir` и `_filedir` перехвачены: вызов с `-d` — вид
  `dirs`, без — `files`. Своего completion у программы нет
  (`_comp_complete_minimal`, нет `complete -p`) — `files`: так Tab ведёт
  себя по умолчанию. Иначе — `words` и `COMPREPLY` (подкоманды, хосты,
  службы, ветки); пустой `COMPREPLY` без вызова filedir — тоже `files`.
  Кандидаты покрывают не меньше половины `programs()` (после `sudo`, `env`,
  `time` completion предлагает все команды) — вид `program`: так позиция
  имени программы узнаётся без перечня этих утилит. Таймаут 1 с; запрос
  не ответил — первые два слова и длина запоминаются до конца процесса, и
  такие же и более длинные запросы с ними сразу получают `None`
  (`systemctl restart` — 3.75 с), а короткие идут как раньше
  (`systemctl --user` — 0.03 с).
- **`options(words)`** -> список ключей команды `words` (от имени программы:
  `["git", "commit"]`). По порядку, до первого непустого: completion на
  позиции с `cur="-"` и `cur="--"`; `man` (широкий `MANWIDTH`, `LC_ALL=C`;
  при подкоманде сначала страница `prog-sub`); `prog
  --help` (только программа из PATH вне домашнего каталога, которую
  пользователь не может переписать, — `trusted()`; таймаут 2 с,
  `stdin=/dev/null`, свой сеанс процессов, при таймауте группа убивается,
  `LC_ALL=C`). Текст man и справки разбирает `_comp_compgen help -` из
  bash-completion — свой парсер не пишем. Кеш на время жизни демона.

Все три функции не бросают исключений наружу: при сбое — `None` / пустой
ответ, а сообщение копится в модуле; `shell.to_command` забирает их
(`complete.drain()`) и пишет в журнал, каждое — один раз на процесс.

### `shell._fit(toks, cwd)` — новый шаг правил

Идёт по токенам слева направо, держит «текущую команду» — слова от её начала.

1. **Имя программы** — первый токен и токен после `sudo`, `|`, `&&`, `;`.
   Если имени нет в `programs()`, пробуем склейку 1–3 соседних слов
   («пай тест» -> `pytest`) и для каждой — по порядку:
   - точное совпадение после `translit` / `english` — берём;
   - нечёткое — только для кириллицы от 4 букв (латиницу уже выбрали
     `WORDS` или whisper: `push` нечётко ушёл бы в `pushd`): сходство
     ≥ 0.78 и отрыв ≥ 0.10 от ближайшего соперника, не начинающегося с
     имени лидера.
   Не нашлось — токен остаётся как есть (дальше решает LLM). Имя,
   подобранное нечётко или транслитом русского слова, возвращается как
   сказано по правилам из «Замеров» — тогда фраза уходит в LLM.
   Первое слово команды не программа — позиции после него не
   спрашиваются: Tab предложил бы файлы.
2. **Позиция `words`** — слово, которого нет среди кандидатов, нечётко
   сопоставляется с ними (схема `_match_loose`: порог и отрыв). Списки
   короткие, порог ниже, чем у программ; величину замерить на настоящих
   списках git / systemctl / docker / apt первым шагом плана и записать в
   комментарий.
3. **Позиция `dirs`** — путь собирается `_walk` из этого и следующих слов,
   как сейчас у `cd`. Особый случай `cd`/`pushd` в `rules()` удаляется:
   completion сам говорит, что у `cd` аргумент — каталог.
4. **Позиция `files`** — `_resolve` / `_walk` с `file_ok`, как сейчас.
5. **Ключ с кириллицей** (`--хелп`, `--олл`) — нечёткое сопоставление
   `translit` / `english` с длинными ключами из `options()` («два минуса
   хелп» -> `--help`).
6. `position()` вернул `None` — поведение сегодняшнее: аргумент
   разрешается как путь.

LLM зовётся по тем же правилам, что сейчас: первый токен после `_fit` — не
программа, слов больше одного.

### `WORDS` и `SOUNDS`

- Порядок для имени программы: исключения `WORDS` -> подбор. Исключения
  проверяются раньше подбора, потому что подбор не просто промахивается, а
  уверенно находит другое («тач» -> `tac`).
- Остаются (по замеру выше): тач, хед, тейл, курл, питон, клод/клауде/…,
  код/ходе, трейсрут, хуиз, скрин, эпт, анзип, найти; произношения по
  буквам, которые перехватило бы слово покороче («эс си пи»); «рут»; слова
  флагов, которые не ключи («инсталл», «нейм» и т.п. — проверить по одному).
- Удаляются записи, у которых без них результат тот же. Решает разовая
  проверка: каждая запись — фраза с ней и без неё; список удалённых — в
  сообщении коммита.
- В `SOUNDS` добавляется `ктл -> ctl`: правило произношения, а не перечень;
  поднимает «системктл» до 0.89 (было 0.78), «резолвктл» до 0.84 (0.74),
  «кубектл» до 1.00 (0.86).

## Журнал и приватность

Кандидаты позиций — это хосты из `~/.ssh/config`, имена файлов, веток и
служб. В журнал они не пишутся; только число кандидатов и вид позиции, текст
— через `shown()`.

## Отказы

| Что | Что будет |
|---|---|
| нет bash или bash-completion | `position()` -> `None`: аргументы разрешаются как пути, как сегодня, кроме `cd` — имя каталога из нескольких слов без «слэш» не склеивается; одна строка в журнал на процесс |
| completion завис или упал | таймаут 1 с, `None` для этой позиции |
| completion с теми же первыми двумя словами уже зависал | не спрашиваем: сразу `None` для позиции той же длины и длиннее, короткие спрашиваем; в журнале одна строка |
| слово похоже на свой скрипт пользователя (`~/bin`, `~/.local/bin`, любой файл, который он может переписать) | `--help` не запускается, ключи — только из completion и man |
| `--help` завис или ждёт ввод | таймаут 2 с, группа процессов убита, ключей нет |
| нет man и программы нет в PATH | ключей нет, кириллический ключ остаётся как сказан |
| исключение в `_fit` | ловится в `rules` (её зовёт и повторный разбор без лишнего слога), в журнал — вид и место без текста, фраза вставляется как сказана |

## Тесты

`test_shell.py`, всё в `sandbox()`, без настоящих каталогов пользователя:

- каталог `bin` с подставными программами (`atlasctl` и т.п.) в PATH теста;
- их completion через `BASH_COMPLETION_USER_DIR`: подкоманды и позиция
  `filedir -d`;
- подставная man-страница через `MANPATH`; программа только с `--help`;
  программа, у которой `--help` зависает.

Случаи:

- нечёткое имя программы и склейка двух слов;
- нечёткая подкоманда;
- позиция каталога — `_walk`; позиция файла — `_resolve`;
- `--хелп` -> `--help` из man и из `--help`;
- слова намерения не становятся программой, LLM зовётся;
- нет bash-completion — результат как без `_fit`;
- `--help` завис — таймаут, фраза собрана;
- все прежние случаи `test_shell.py` проходят. `voiced.py` берёт из
  `shell.py` только `LETTERS`, их план не трогает — `test_commands.py` не
  нужен.

## Не входит

- Постоянный bash-сопроцесс (по замеру не нужен).
- Алиасы и функции из `~/.bashrc` (нужен `bash -i` с побочными эффектами).
- Проверка коротких ключей по списку.
- Чтение PATH из окружения оболочки терминала (совпадает со службой).
